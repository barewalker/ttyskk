# ttyskk

端末の中だけで完結する SKK 日本語入力です。

擬似端末で子プロセスを包み、キー入力を受け取って、**変換の済んだ文字列だけ**を子プロセス
へ渡します。変換の途中の文字は端末に直接重ねて描くため、子アプリの画面には一度も現れま
せん。

入力メソッドが端末アプリと同じ層にいるので、キーは必ず「端末多重化器 → ttyskk → 子アプリ」
の順に流れます。画面全体を受け持つ入力メソッドと多重化器が `Ctrl+Z` を取り合う、という
問題が起きません。

```sh
ttyskk                  # $SHELL を包みます
ttyskk -- claude        # 特定のコマンドを包みます
ttyskk vim memo.txt
```

同じ変換エンジンは fcitx5 の入力メソッドとしても動きます。辞書と学習を端末と分け合うので、
どちらで覚えた語も両方で先に出ます (「[GUI で使う](#gui-で使う-linux-fcitx5)」)。

- 動く環境 … Linux と macOS。WSL2 でも動きますが、Windows そのものでは動きません
  (POSIX の擬似端末を使っているためです)
- 必要なもの … POSIX の擬似端末と、VT100 系のエスケープ列を解する端末。tmux / screen /
  SSH / mosh のどれと組み合わせても、また何も挟まなくても動きます

## インストール

[crates.io](https://crates.io/crates/ttyskk) にあります。**端末で使うぶんにはこれだけで
足ります** (GUI の入力メソッドと C ABI は付いてきません)。Rust 1.88 以降が必要です。

```sh
cargo install ttyskk
```

変換には SKK の辞書が要ります。

```sh
sudo apt install skkdic     # Debian / Ubuntu / WSL
sudo pacman -S skk-jisyo    # Arch
```

置き場所が違う場合は環境変数 `TTYSKK_JISYO` で指定してください。

設定は無くても動きます。変えたくなったら、設定できる項目を全部並べた見本を書き出せます。

```sh
mkdir -p ~/.config/ttyskk
ttyskk --config-example > ~/.config/ttyskk/config.toml
```

公開した版より先を追いたいときは GitHub から直接入れられます。詳しくは
[`docs/install.md`](docs/install.md) をご覧ください。

## 最初の一歩

SKK は**打つ人が変換の区切りを決める**入力方式です。慣れるまでの手順は次の三つだけです。

1. `Ctrl+J` でかなモードに入ります
2. 漢字にしたい語は**先頭を大文字**で打ちます。`Kanji` と打つと `▽かんじ` になります
3. `space` で変換します。`▼漢字` になったら `Ctrl+J` (または次の文字) で確定します

画面に出る `▽` は「変換したい語を入力している」印、`▼` は「候補を選んでいる」印です。
どちらの状態でも `Ctrl+G` で取り消せます。

```
C-j        かなモードへ
Kanji      → ▽かんじ
space      → ▼漢字
space      → ▼幹事      (次の候補へ)
C-j        → 漢字を確定
l          → ASCII モードへ戻る
```

送り仮名のある語は、送り仮名の先頭も大文字で打ちます。`UgoKu` と打つと `▼動く` になります。

## キー操作

### モードの切り替え

| キー | 動作 |
|---|---|
| `C-j` | かなモードへ入ります |
| `l` | ASCII へ戻ります |
| `L` | 全角英数へ移ります |
| `q` | ひらがな ⇄ カタカナ |
| `C-q` | ひらがな ⇄ 半角カタカナ |

いまどのモードにいるかは**カーソルの見た目**で分かります。既定ではカーソルのセルに色を
敷きます (ひらがなは緑、カタカナは水色、半角カタカナは青緑、全角英数は紫、ASCII は色を
敷きません)。

```toml
[behavior]
mode_marker = "cell"     # カーソルのセルに色を敷きます (既定)
mode_marker = "symbol"   # カーソルのセルに半角の記号を出します
mode_marker = "beside"   # カーソルの右隣のセルに色を敷きます
mode_marker = "letter"   # カーソルの直後に あ / ア / 半 / Ａ を出します
mode_marker = "off"      # 何も描かず、カーソルの形だけで表します
```

**ASCII モードでは何も描きません**ので、日本語を打っていないときの透過は保たれます。

端末多重化器を挟むと色や形が外側まで届かないことがあり、そのときは `beside` や `letter`
が確実です。記号の選び方や多重化器ごとの事情は
[`docs/mode-marker.md`](docs/mode-marker.md) にまとめました。

### 変換

| キー | 動作 |
|---|---|
| 大文字 | 変換の開始 (`▽`)。`Kanji` → `▽かんじ` |
| 途中の大文字 | 送り仮名の始まり。`UgoKu` → `▼動く` |
| `;` | 次の一打鍵を大文字として扱います (Shift の代わり。**既定では割り当てなし**) |
| `space` | 変換する / 次の候補へ |
| `x` | 前の候補へ |
| `X` | いまの候補を利用者辞書から取り除きます |
| `C-j` | 候補を確定します |
| `C-g` | 取り消します |
| `q` | `▽` の内容をカタカナにして確定します |
| `C-q` | `▽` の内容を半角カタカナにして確定します |
| `Q` | 空の見出し語で変換を始めます (複合語向け) |
| `/` | ASCII の見出し語で変換します |
| `C-l` | `▽` の内容を、打った綴り (ASCII) に置き換えます |
| `>` | 接頭辞 (`▽` の途中) / 接尾辞 (`▼` の途中) の変換 |
| `TAB` | 見出し語を補完します / 次の補完へ |
| `S-TAB` | 前の補完へ |
| `BS` | 一文字戻ります |
| `C-b` / `←` | `▽` の見出し語の中でカーソルを左へ |
| `C-f` / `→` | 同じく右へ |
| `C-a` / `C-e` | 見出し語の先頭 / 末尾へ |
| `C-d` | カーソル位置の一文字を消します |

候補が 5 つ目に達すると横並びの一覧が出て、`a s d f j k l` で選べます。一覧に載らない分は
末尾に `[残り 12]` と件数で出ます。ここに挙げたキーはすべて設定で変えられます。

`Enter` は候補の確定だけを行い、改行は送りません。端末では改行が「コマンドの実行」を意味
するため、変換の確定と取り違えると事故になるからです。

### 打ってしまってから英数にする

かなで打ち始めてから「これは英語のままがよかった」と気づいたとき、`C-l` を押すと **`▽` の
内容が打った綴りに変わります**。`/` で始めたときと同じ ASCII の見出し語に移るので、そこから
続きを打つのも、`space` で変換するのも、`C-j` で確定するのも自由です。取り消して打ち直す
必要はありません。

```
Kanji      → ▽かんじ
C-l        → ▽kanji
C-l        → ▽Kanji      (続けて押すと 小文字 → 先頭大文字 → 全て大文字 と巡ります)
C-l        → ▽KANJI
C-j        → kanji を確定 (かなモードのまま)
```

**取り消しは一段ずつです。** `C-g` を押すと、まず元の かな の見出し語に戻ります。もう一度
押せば普段どおり `▽` ごと取り消します。`TAB` の補完を `C-g` で戻せるのと同じ流儀で、ASCII に
移ったのが勘違いだったときに打ち直さずに済みます。

```
▽kanji     → C-g → ▽かんじ → C-g → (取り消し)
```

覚えているのは**打鍵そのもの**で、かなから綴りを逆算するのではありません。`Shift` と打てば
`▽しft` になりますが、戻るのは `sihuto` ではなく `shift` です。`Hello` のようにかなにならない
綴りは `▽へllお` と崩れた姿になりますが、`C-l` で `hello` に揃います。

`▽` は大文字でしか始められないので、そのままでは綴りが必ず大文字始まりになります。一度目を
小文字にしてあるのはそのためです。巡回が効くのは**押した直後だけ**で、間に何か打てば終わり
ます (`html` のように `l` を含む語も普通に打てます)。カーソルを動かしたり `TAB` で補完したり
すると綴りを追えなくなるので、そのときは何も起こりません。

既定が `C-l` なのは、ASCII の見出し語の中では打った文字がそのまま入るためです。`l` のような
文字キーだと、その文字自身が打てなくなります。`▽` の外では素通しするので、shell の画面消去は
そのまま効きます。

### Shift を使わずに打つ (前置キー)

**既定では割り当てがありません。** 使うには前置キーを決めます。

```toml
[keys]
sticky = ";"
```

こうすると `;` を前に置いたとき、次の一打鍵を大文字として扱います。Shift の同時押しを
しなくても `▽` に入れます。

```
;kanji     → ▽かんじ      (Kanji と打ったのと同じ)
;ugo;ku    → ▼動く        (UgoKu と打ったのと同じ)
;;         → ;            (二度押すと ; そのものが出ます)
```

押した時点で**どこを切るのかが画面に出ます**。次の一打鍵まで画面が動かないと、効いたのか
どうか分からないためです。印は ddskk が実際に入れるものと同じで、`▽` が「ここから読み」、
`*` が「ここから送り仮名」を表します。

```
;          → ▽           (次の打鍵から見出し語)
;kanga     → ▽かんが
;          → ▽かんが*     (次の打鍵が送り仮名の頭)
;kanga;e   → ▼考え
```

Shift でやっていることは大文字を打つことではなく、**「ここから読み」「ここから送り仮名」
という区切りの宣言**です。前置キーはその宣言を同時押しから打つ順番に移し替えたもので、
宣言そのものは残ります (無くせば読みの範囲を推し量ることになり、SKK ではなくなります)。
引き換えに打鍵が一つ増えるので、同時押しと打鍵数のどちらを取るかという選択になります。

かなモードでだけ効きます。ASCII・全角英数と、`/` の ASCII 見出し語では素通しします。

既定を空にしてあるのは、**割り当てた文字が二度押しでしか打てなくなる**ためです。`;` に
割り当てれば `;` 自身は `;;` になります。Shift を押せる人には打鍵が増えるだけなので、
要る人が選ぶ形にしました。

**AZIK では `;` が「っ」なので食い合います** ([AZIK](#azik-拡張ローマ字入力))。前置キーが
先に効くため「っ」が打てなくなります。AZIK と併せるなら別のキーへ移してください。
`--check-config` を呼ぶと、この食い合いを断ります。

小指を左下へ伸ばすのが煩わしいだけなら、鍵盤の側で Shift の位置を変えるほうが打鍵数を
増やさずに済みます (無変換キーや Home 行への割り当て)。端末はキーを離した通知を受け取れ
ないので、その手当ては入力の最下層 (xremap など) でしか行えません。

### 打ち間違いを直す

`▼` の途中で `C-g` を押すと `▽` に戻ります。そこから `C-b` / `C-f` (または矢印) で見出し語
の中を動き、`BS` で手前の一文字、`C-d` でカーソルの一文字を消して、`space` で変換し直せ
ます。最初から打ち直さずに済みます。

```
Kanji space    → ▼漢字
C-g            → ▽かんじ
C-b C-b        → ▽かんじ   (「ん」の上にカーソルがあります)
C-d            → ▽かじ
space          → ▼家事
```

カーソルのある一文字は反転して出ます。重ね描きの間は端末のカーソルを隠している (そうしな
いと描き替えのたびにちらつきます) ため、位置はこの一文字で示しています。

移動が効くのは `▽` の中だけで、それ以外では押したキーがそのまま子アプリへ渡ります。

候補一覧の出し方は 2 通りから選べます。

```toml
[candidates]
layout = "inline"   # 入力中の行に続けて横並び (既定)
layout = "float"    # カーソルの下の行に一行で浮かせます (最下行なら上の行)
```

`inline` は行が伸びるぶん折り返すことがあります。`float` は行が伸びず縦にも広がらないので、
`nvim` の補完の一覧のような縦長の表示とも重なりにくくなります。浮かせた行の元の内容は画面
の控えから書き戻すため、`vim` や Claude Code の枠線の上に出しても消えません。

## 変換を助ける仕組み

### 自動変換

**区切りの文字が来ると、`space` を押さなくても変換が始まります。** `Honnyakuwo` と打てば
`を` の直前までの「ほんやく」で変換に入り、`を` は候補の後ろに置かれます。

```
▽ほんやく  →(を)→  ▼翻訳を  →(space)→  ▼飜訳を
```

引き金の文字は見出し語に含めません (含めると辞書を引けないためです)。既定の顔ぶれは ddskk
の `skk-auto-start-henkan-keyword-list` と同じです。

```toml
[behavior]
auto_start_henkan = "を、。．，？」！；：);:）”】』》〉}]?.,!"
auto_start_henkan = []   # 空にすると自動変換をしません
```

### 補完

`▽` の途中で `TAB` を押すと、前方一致する見出し語に伸ばします。もう一度押すと次の候補へ、
`S-TAB` で戻ります。`C-g` は補完だけを取り消します。

```
Nihon TAB      → ▽にほんご 日本語 [1/12]
      TAB      → ▽にほんじん 日本人 [2/12]
      space    → ▼日本人
```

**伸ばした見出し語が何になるかを添えます。** 見出し語だけでは選べないためです。「かんじゃ」
が患者なのか冠者なのかは変換するまで分からず、それでは `TAB` を送るたびに一度 `space` で
確かめて戻ることになります。出るのは「`space` を押したら出る候補」「その注釈」「いま何番目か」
の三つです。

補完の元は**利用者辞書が先、共有辞書が後ろ**です。そこにあるのは実際に使った語なので、
17 万語から拾ったものより当たりやすくなります。直接入力中の `TAB` は子アプリへそのまま
渡るので、シェルの補完は損ないません。

### 打つそばから見せる (動的補完)

`TAB` を押す前から補完を見せられます。既定では出しません。

```toml
[behavior]
dynamic_completion = "single"    # 続きを一つだけ薄く添えます
dynamic_completion = "multiple"  # 前方一致する見出し語を数件並べます
dynamic_completion = "off"       # 出しません (既定)
```

```
Nihonn         → ▽にほんご          "single" … 薄いのは補った「ご」だけ
               → ▽にほん にほんご にほんかい にほんじん   "multiple"
TAB            → ▽にほんご 日本語 [1/12]
```

薄字なのは**補った分だけ**で、自分が打った見出し語は太字と下線のままです。どこまでが打鍵
かが色で分かるので、そのまま `space` を押しても補った分は混ざりません。取り込むときは
`TAB` を押します。押したあとは、いつもの補完と同じように次の候補へ送れます。

`"multiple"` の並べ方は候補一覧の設定 (`candidates.layout`) に従います。`float` にして
あれば、補完もカーソルの下の行に浮きます。

出るのは `▽` の末尾で**かなが一区切りついたところ**だけです。ローマ字が打ちかけのうち
(`▽にほんg`) や、送り仮名に入ったあと、見出し語の途中へ戻ったあとは出しません。伸ばす先が
決まらない、あるいは伸ばす場所が末尾ではないためです。

fcitx5 の入力メソッドでも同じ設定で出ます。あちらは薄字にできないので、補った分は**下線を
外して**示し、カーソルは打った分の末尾に置きます。

### 送り仮名ごとの学習

**送りありの見出し語は、送り仮名が違っても同じになります。** 「大きい」は `OoKii`、「多く」
は `OoKu` と打ちますが、辞書を引く見出し語はどちらも `おおk` です。

見出し語だけで学習すると、片方がもう片方を引きずります。「大きい」を確定したあとに「おおく」
と打つと `▼大く` が出てしまいます。そこで**確定するたびに送り仮名ごとの宛先も覚えます**。

```
おおk /大/多/[き/大/]/[く/多/]/
        ~~~~~  ~~~~~~~~~~~~~~~~
        候補   送り仮名ごとの宛先
```

ddskk・CorvusSKK と同じ書き方なので、利用者辞書を分け合っても互いに読めます。他の実装が
書いた宛先も消しません。

```toml
[behavior]
okuri_match = "first"   # その送り仮名の候補を先頭へ寄せます (既定)
okuri_match = "only"    # その送り仮名の候補だけを出します
okuri_match = "off"     # 使いません (ddskk の既定と同じ)
```

既定が `first` なのは**候補を隠さない**からです。宛先が貯まっていない見出し語では並びが
変わらないので、有効にして困ることがありません。

### 接頭辞・接尾辞の変換

辞書に無い複合語をその場で組み立てます。`SKK-JISYO.L` にはこの形の項目が約 1,200 あります。

```
Aka> → ▼赤              (▽あか> として引きます。> を押した時点ですぐ変換します)
Pen space → ▼ペン       → 赤ペン

Kandou space → ▼感動
> → ▽>                  (候補を確定し、> から始まる見出し語を立てます)
teki space → ▼的        → 感動的
```

**続けて確定した語は繋げて覚えます。** 「さい>」→ 再 のあと「りよう」→ 利用 と確定すると
`さいりよう /再利用/` が利用者辞書に入ります。ddskk の `skk-learn-combined-word` と同じ
振る舞いで、`[behavior] learn_combined = false` で止められます。

### 数値変換

見出し語に数字が含まれると、その部分を `#` に置き換えた見出し語でも辞書を引きます。
`SKK-JISYO.L` にはこの形の項目が 490 あり、これが無いとどれも引けません。

```
Dai5kai space   → ▼第５回 → 第5回 → 第五回
Q1234en space   → ▼１２３４円 → 1234円 → 1,234円 → 千二百三十四円
```

数字は大文字にできないので、数字から始まる見出し語は `Q` で変換を先に始めます。候補の `#`
に続く一桁が型を表します。

| 型 | 1234 が | 型 | 1234 が |
|---|---|---|---|
| `#0` | 1234 | `#3` | 千二百三十四 |
| `#1` | １２３４ | `#5` | 壱阡弐百参拾四 |
| `#2` | 一二三四 | `#8` | 1,234 |

`#9` は将棋の棋譜です (2 桁を `34` → `３四`)。**学習は `#` のままの形で書き戻します** ——
数字を戻した形で覚えると、その数字専用の項目ができてしまうためです。

### 候補の削除

`▼` の途中で `X` を押すと、いま選んでいる候補を利用者辞書から取り除きます。誤って登録した
語や、学習で先頭に来てしまった誤変換を消すために使います。

**共有辞書には手を触れません。** そちら由来の候補は次の変換でも出ます。消えるのは学習に
よる先頭への繰り上がりだけです。

### 辞書登録

候補が見つからないとき、または候補を出し切ったところでもう一度 `space` を押すと登録に移り
ます。見出しが `[登録:てがき]` の形で出るので、そのまま打ち込んで `Enter` を押します。

| キー | 動作 |
|---|---|
| `Enter` | 登録して確定します |
| `C-g` | 登録をやめて `▽` に戻ります |
| `BS` | 一文字消します。空のところで押すと `▽` に戻ります |

登録の中でも変換はそのまま使えます。未知語が出てくればもう一段積まれ、`[[登録:...]]` の
ように括弧が重なります。

住所や署名のように長いものは、登録画面で打つより**定型文として書く**方が楽です (次の節)。

## 定型文

住所・電話番号・メールの署名のように「打つのが面倒で、内容が決まっている」文字列は、手元の
編集器で一覧を見ながら書けます。

```sh
ttyskk --edit-snippets            # 一覧を開きます
ttyskk --edit-snippets かいしゃ   # 見出し語を埋めた雛形を足して開きます
```

書式は **VS Code のスニペット** (`*.code-snippets`) です。nvim の LuaSnip も同じファイルを
読めるので、編集器と入力メソッドで一つのファイルを分け合えます。

```jsonc
{
    "会社住所 (日本語)": {
        "prefix": "かいしゃじゅうしょ",
        "body": ["東京都港区…"],
        "description": "日本語"
    },
    "メール署名": {
        "prefix": "しょめい",
        "body": ["竹内 光明", "株式会社レスカ", "TEL 03-XXXX-XXXX"]
    },
}
```

`prefix` が見出し語、`body` が候補、`description` が候補の右に出る注釈です。`body` を行の
並びにすると改行で繋がるので、SKK の辞書には書けない「改行を含む定型文」も持てます。

**学習では動きません。** 並びはファイルに書いたとおりに出ますし、確定しても利用者辞書へ
写しません。住所を書き換えたときに古い住所が先頭に残り続けるのを避けるためです。

日付を差し込む書き方 (`$CURRENT_YEAR` など) や、`$1` を置いて一つずつ埋める使い方は
[`docs/snippets.md`](docs/snippets.md) をご覧ください。

## 入力方式

### AZIK (拡張ローマ字入力)

**「2 文字めに《ん》が来る」「二重母音」という、日本語に多い並びを 2 打で打てます。**

```toml
[behavior]
romaji = "azik"    # 既定は "default"
```

母音キーの代わりに**その下のキー**を打つと「母音 + ん」になります (撥音拡張)。

| | あ段 | い段 | う段 | え段 | お段 |
|---|---|---|---|---|---|
| キー | `z` | `k` | `j` | `d` | `l` |
| 例 | `kz` かん | `kk` きん | `kj` くん | `kd` けん | `kl` こん |

母音キーの**近くのキー**が二重母音になります。

| | あい | うう | えい | おう |
|---|---|---|---|---|
| キー | `q` | `h` | `w` | `p` |
| 例 | `sq` さい | `kh` くう | `sw` せい | `kp` こう |

ほかに次の決まりがあります。

- **「っ」は `;`、長音は `:`、単独の「ん」は `q`** (`nn` も打てます)
- **シャ行は `x`、チャ行は `c`** —— `sh` `ch` は二重母音の拡張に使うためです
- **小書きのかなは `l` を前置します** (`la` ぁ、`lyo` ょ) —— `x` をシャ行に譲ったためです
- 拗音の `y` は `g` でも打てます (`kga` きゃ)。左右の交互打鍵になります
- 頻出の並びは 2 打です (`kt` こと、`ds` です、`mn` もの、`sr` する)

裏を返すと、**子音の重ねで促音を打つ綴りは使えなくなります** (`tt` は「たち」、`kk` は
「きん」)。AZIK では促音に `;` を使います。取り決めの一覧は
[`docs/azik.md`](docs/azik.md) にあります。

その `;` は[前置キー](#shift-を使わずに打つ-前置キー)に選びやすい位置でもあります。両方を
`;` にすると前置キーが先に効いて「っ」が打てなくなるので、AZIK と併せるなら前置キーは
別のキーへ移してください。

### 句読点

`.` と `,` から出る文字は四通りから選べます (ddskk の `skk-kutouten-type` と同じです)。

```toml
[behavior]
kutouten = "jp"      # 。 、 (既定)
kutouten = "en"      # ． ，
kutouten = "jp-en"   # 。 ，
kutouten = "en-jp"   # ． 、
```

差し替わるのは `.` `,` から出るものだけで、`z.` の `…` や `z,` の `‥` はそのままです。

## 画面の文脈で候補を選び分ける (試験的)

> **試験的な機能です。** 既定で有効ですが、効き方はまだ日常の使い心地で測っている段階に
> あります。将来の版で作りが変わるか、取り除かれることがあります。そのときも設定に書いた
> ままで壊れないようにします (知らない項目は読み飛ばします)。

**日本語は同音異義語が多すぎます。** 「こうせい」は `SKK-JISYO.L` に 20 を超える候補があり、
見出し語だけでは決めようがありません。最近使った順に並べても、話題が変われば外れます。

ttyskk は**子アプリの画面の控え**を持っているので、子アプリが書いた文字まで手掛かりにでき
ます。画面はペインごとなので、話題の切れ目が自然に入ります。

| 画面にあるもの | こうせい | こうえん |
|---|---|---|
| (何も無い) | 構成 公正 校正 | 公園 講演 公演 |
| 「新聞の記事をあらためて読み直す」 | **校正** 構成 公正 | |
| `please proofread this draft` | **校正** 構成 公正 | |
| 「厚生労働省の統計によると」 | **厚生** 構成 公正 | |
| 「劇団の公演は来週です」 | | **公演** 公園 講演 |
| 「作家をまねいて話をきく会」 | | **講演** 公園 公演 |

手掛かりは「候補そのものが画面にあるか」と「注釈の共起語が画面にあるか」の二つで、どちらも
**辞書に既にある情報**を使います。余分なファイルは持ちません。`SKK-JISYO.L` は
`校正;proofread.「新聞の-」` のように用例と訳語を注釈に持っているので、画面に `proofread`
や「新聞」があれば校正が上がります。

```toml
[behavior]
context_order = true          # 既定です。順序を指で覚えているなら false にします
context_half_distance = 200   # 重みが半分になる距離 (文字数)
```

**手掛かりが無ければ並びを変えません。** 関わりの無い画面で悪くなることはありません。
引き換えに、同じ読みが画面によって違う順で出るようになります。

**GUI (fcitx5) でも効きますが、届く範囲が違います。** GUI で使えるのは「いま打ち込んでいる
入力欄の中身」だけで、画面に何が映っていても入力メソッドからは見えません。編集器やメールの
本文のように文章が溜まっている入力欄では効きますが、検索窓のように中身が数文字しかない場では
手掛かりがありません。

重みの決め方、効き方を測るための例文などは
[`docs/context-order.md`](docs/context-order.md) にまとめました。

## 設定

キーの割り当てなどは `~/.config/ttyskk/config.toml` で変えられます。書いた項目だけが既定を
上書きするので、変えたいものだけ書けば足ります。

設定できる項目を全部、既定値のまま並べて `#` で無効にした見本を実行ファイルに埋め込んで
あります。書き出して、変えたい行の `#` を外すのがいちばん早い方法です。

```sh
mkdir -p ~/.config/ttyskk
ttyskk --config-example > ~/.config/ttyskk/config.toml
```

```toml
[keys]
kana = "C-o"                    # かなモードへ入るキーを変えます
cancel = ["C-g", "esc"]         # 複数割り当てるなら並びで書きます
select = ["1", "2", "3", "4"]   # 候補一覧から選ぶキー (個数が一頁の候補数になります)
move_left = "left"              # ▽ の中の移動を矢印だけにします

[candidates]
inline = 2                      # 2 つ目の候補から一覧を出します

[behavior]
ascii_keys = ["esc", "C-c"]     # 押すと ASCII モードへ戻るキー
mode_marker = "letter"          # モードの印の出し方
learn_combined = false          # 接頭辞・接尾辞に続く語を繋げて覚えません
```

キーの書き方は `C-j` / `Ctrl-j` / `ctrl+j`、`space` `enter` `tab` `esc` `bs`、`left` `right`
`up` `down` `home` `end`、`q` `/` のような一文字そのものです。矢印と `home` / `end` は端末に
よって送られる形が違いますが、名前で書けばその全部が割り当てになるので、どの端末でも同じ
ように効きます。

**書き換えは動いている ttyskk にそのまま反映されます。** 起動し直す必要はありません。
書き方を間違えた設定は捨てられ、それまでの設定が使われ続けます (変換の途中でキーが効かなく
なる事態を避けるためです)。手元で確かめるには次を使います。

```sh
ttyskk --check-config
```

**知らない項目があっても起動は止まりません。** 読み飛ばしたことを知らせて、残りはそのまま
効かせます。設定は複数の環境に配られる一方、本体の版は環境ごとにずれるためです。

`Enter` だけは割り当てを変えられません。変換中は確定として働き、そうでなければそのまま子
アプリへ流します。

## vim / nvim と使う

**`Esc` と `C-c` を押すと ASCII モードへ戻ります。** 挿入モードを抜けたのにかなモードが
残っていると、次の `dd` や `:w` が日本語になってしまうためです。どちらも子アプリにはそのまま
渡るので、**vim 側の設定は要りません**。

```sh
ttyskk -- nvim memo.txt
```

`i` で挿入 → `C-j` でかな → 打つ → `Esc` で ASCII、という往復がそのまま回ります。増やしたい
ときは設定で足せます。

```toml
[behavior]
ascii_keys = ["esc", "C-c", "C-o"]
```

`ascii_keys` は押されたキーを見張るので、`inoremap <C-l> <Esc>` のような割り当てには付いて
いけません。カーソルの形を見れば抜け方に依らないので、そちらで追う設定もあります。

```toml
[behavior]
follow_cursor_shape = true
```

vim / nvim は挿入モードで棒、ノーマルモードでブロックにするため、棒でなくなったらかなモード
を降ろします。**打ちかけがあるうちは降ろしません。** 既定は無効です (カーソルの形を別の意味
で使うアプリもあるためです)。

## ローマ字で日本語を探す (migemo)

`ttyskk migemo` は、ローマ字に当たる日本語を探すための正規表現を書き出します。

```console
$ ttyskk migemo kaigi
(?:kaigi|かいぎ|カイギ|会議|回議|怪魚|懐疑|改行|海[技魚]|解義|…)
```

ローマ字からかなへの変換ではなく、読みから見出し語を引くので**漢字にも当たります**。日本語
入力に切り替えずに絞り込めるので、fzf のプロンプトや `/` 検索から使えます。

```
ttyskk migemo [--flavour vim|rg] [--limit N] <ローマ字>
```

**方言は必ず選んでください。** `\%(` を ripgrep に渡すと、何も見つからないまま静かに終わり
ます。既定は `rg` (ripgrep・Rust の regex 用) で、Vim / Neovim には `vim` を渡します。

索引を作ると引くのが速くなります (200 ms → 26 ms)。

```sh
ttyskk migemo --build-index
```

Neovim から呼ぶ書き方や索引の置き場所は [`docs/migemo.md`](docs/migemo.md) にあります。

## GUI で使う (Linux, fcitx5)

同じ変換エンジンを fcitx5 の入力メソッドとして動かせます。**辞書と学習を端末の ttyskk と
分け合う**ので、どちらで覚えた語も両方で先に出ます。設定 (`config.toml`) も同じものを読み
ます。

こちらはソースからの組み立てが要ります (fcitx5 の addon は版に結びつくため、使っている
fcitx5 と同じ環境で組む必要があります)。

```sh
sudo apt install fcitx5-modules-dev extra-cmake-modules cmake build-essential
git clone https://github.com/barewalker/ttyskk && cd ttyskk/fcitx5
cmake -B build -DCMAKE_INSTALL_PREFIX=/usr && cmake --build build
sudo cmake --install build
setsid fcitx5 -r -d >/dev/null 2>&1 </dev/null
```

`fcitx5-configtool` の入力メソッド一覧に **ttyskk** が出るので追加してください。いまのモード
は札のアイコン (あ / ア / 半 / Ａ / A) で分かります。

**設定画面 (歯車) には設定項目を置いていません。** 設定を fcitx5 側にも並べると、同じ項目の
置き場所が二つになるためです。歯車を開くと、書き換える先を案内する画面が出ます。端末で書き
換えたものを読み直させるだけなら `fcitx5-remote -r` でも足ります。

作りは [`docs/fcitx5-addon.md`](docs/fcitx5-addon.md) にまとめてあります。

## 辞書と学習

| 種類 | 既定の場所 |
|---|---|
| 共有辞書 | `/usr/share/skk/SKK-JISYO.L`、`/run/host/usr/share/skk/SKK-JISYO.L` |
| 利用者辞書 | `$XDG_DATA_HOME/ttyskk/user.dict` |
| 定型文 | `$XDG_DATA_HOME/ttyskk/snippets.code-snippets` |
| 同梱辞書 | 実行ファイルに埋め込み (`dict/SKK-JISYO.ttyskk`) |

`TTYSKK_JISYO` (`:` 区切り) と `TTYSKK_USER_JISYO` で変えられます。EUC-JP と UTF-8 のどちら
でも読めます。引く順は**利用者辞書 → 定型文 → 共有辞書**です。定型文が共有辞書より前に来る
のは手で書いたものだからで、「でんわ」に自分の番号を書いたなら「電話」より先に出したいため
です。

確定した候補は先頭へ移り、保存されます。保存は「この起動で覚えたこと」だけをディスクの内容
に重ねる方式なので、**複数の端末で同時に使っても学習を消し合いません**。mosh 越しに使う場合
はリモート側で動くため、辞書と学習がそこに集まり、どの端末から繋いでも同じ変換になります。

丸数字を同梱しています。どの標準辞書にも入っていないためで、`Maru1` または `C1` と打って
`space` で ① が出ます (`C21` で ㉑、`C50` で ㊿)。

### 他の実装から学習を引き継ぐ

skkeleton や fcitx5-skk など、別の SKK 実装で溜めた学習を合流できます。

```sh
ttyskk --import ~/.skkeleton              # skkeleton (nvim)
ttyskk --import ~/.local/share/fcitx5/skk/user.dict
ttyskk --import /mnt/c/Users/<利用者>/AppData/Roaming/CorvusSKK/userdict.txt
```

符号化は自動で見分けます。**既にある候補は動かしません** —— 学習の順序は「最近使った順」
なので、取り込んだものを先頭に置くと、いま使っている語より古い語が前に出てしまうためです。
相手にしかない候補だけを後ろへ足すので、何度実行しても構いません。

利用者辞書がまだ無い初回に限り、`~/.local/share/fcitx5/skk/user.dict` があれば読み込みます。
fcitx5-skk からの乗り換えでは、それだけで学習内容が引き継がれます。

### 複数の環境で学習を分け合う

利用者辞書 (`~/.local/share/ttyskk/user.dict`) を git に載せれば、職場と自宅で覚えた語が行き
来します。**ttyskk を止める必要はありません。**

保存も読み直しも「ディスクの現状を土台に、この起動で覚えたことを重ねる」方式なので、外から
書き換わっても自分の学習を失いません。取り込む側は利用者辞書の更新時刻を見張っていて、
`git pull` で新しくなればその場で読み直します。

```sh
cd ~/.local/share/ttyskk
git init -b main && git add -A && git commit -m "init"
git remote add origin <辞書用のリポジトリ>
git push -u origin main
```

あとは定期的に pull と push を回します。**非対話にしてください** —— 鍵のパスフレーズを聞か
れると、誰も答えられないまま止まります。

```sh
export GIT_SSH_COMMAND="ssh -o BatchMode=yes -o ConnectTimeout=10"
export GIT_TERMINAL_PROMPT=0
```

## 知っておくと困らないこと

### 動いているかをプロンプトに出す

ASCII モードでは何も描かないため、そのままでは**包まれているのかどうかが見た目で分かりま
せん**。ttyskk は子アプリへ環境変数 `TTYSKK_ACTIVE` を渡すので、プロンプトでそれを見れば
示せます (値は包んでいる ttyskk の PID ですが、**見るのは有無だけで足ります**)。
[starship](https://starship.rs/) ならこう書きます。

```toml
format = """
$directory$git_branch$git_status${env_var.TTYSKK_ACTIVE}$character
"""

[env_var.TTYSKK_ACTIVE]
symbol = "⌨"
format = "[$symbol]($style) "
style = "bold cyan"
```

素のシェルでも同じことができます (zsh)。

```sh
setopt prompt_subst
PS1='${TTYSKK_ACTIVE:+⌨ }'"$PS1"
```

### 二重に起動したとき

すでに ttyskk の中にいる場合、二つ目は自分を子で置き換えて (`exec`) そのまま退きます。包み
直しても外側が先にキーを取るので内側は働かず、辞書をもう一部抱えるだけになるためです。承知
のうえで入れ子にしたいときは目印を外してください。

```sh
env -u TTYSKK_ACTIVE ttyskk -- claude
```

### 更新したものに、抜けずに入れ替える

新しい版を入れたあと、**包まれている端末の中から差し替えを頼めます**。

```sh
cargo install ttyskk    # 新しい版を入れる
ttyskk --reload         # いま包んでいる ttyskk を入れ替える
```

**子は生き残ります。** 編集器も、長く動かしているエージェントもそのままで、入力メソッドだけ
が新しくなります。更新のたびに端末を閉じて開き直すのは、中で動いているものほど高くつくため
です。

`exec` はプロセスの中身を入れ替えるだけで、開いてあるファイル記述子も子との親子関係も残り
ます。それを使って擬似端末を開き直さずに渡しているので、繋がりが切れません。**差し替え先が
起動できないときは、そのまま元の姿で動き続けます** — 子を道連れにするくらいなら、差し替えは
次の機会でよいという判断です。

覚えた語はいったん書き出してから渡すので、学習は失われません。入力の途中 (`▽` や `▼`) は
消えるので、変換を確定してから頼んでください。

**差し替えは見た目を変えません。** 画面も PID もそのままなので、効いたかどうかは分かりません。
`--status` が包んでいる ttyskk の中身を答えます。

```sh
$ ttyskk --status
ttyskk 0.4.0 (pid 836698)
  実体   /home/mitch/.cargo/bin/ttyskk
  起きた 2026-08-04 21:30:51
  実体が入れ替わっている。差し替えると新しくなる (ttyskk --reload)
```

最後の行が要点です。`cargo install` したあとにこれを見れば、**差し替える意味があるかどうか**が
分かります。版だけでは足りない (同じ版のまま中身が入れ替わることがある) ので、実体の大きさと
更新時刻で見ています。

#### キー一つで頼む

シェルへ戻れない場面 — 編集器やエージェントの画面の中 — では、キーに割り当てておけます。

```toml
[keys]
reload = "C-]"      # 既定は割り当てなし
```

ttyskk が打鍵の段で受け取るので、子アプリが何であっても同じキーで効きます。`[keys]` に書いた
Ctrl 付きのキーは拡張鍵盤プロトコルの下でも届くので、Claude Code の中でも使えます。その代わり
**割り当てたキーは子アプリへ渡らなくなる**ので、子が使っていないものを選んでください。Ctrl は
英字のほか `@ \ ] ^ _` にも付きます。英字の制御キーは端末・シェル・編集器のどれかが必ず使って
いますが、`C-]` や `C-\` はほとんど空いています。

変換や辞書登録の途中では効きません (打ち込んだものが消えるため)。そのときは押しても素通しで
子へ渡ります。

包んでいるのが古い版 (0.3.x 以前) のときは差し替えられません。その版は合図を知らないので、
一度抜けて起動し直してください。

### 拡張鍵盤プロトコルを使うアプリの下で

Claude Code のような画面全体を使うアプリは、起動時に `CSI > 1 u` (kitty 鍵盤プロトコル) や
`CSI > 4 ; 2 m` (modifyOtherKeys) を有効にします。この状態では `Ctrl+J` が `0x0a` ではなく
`CSI 106;5u` という形で届くため、素朴に読むとモード切り替えが効きません。

ttyskk は **`[keys]` で SKK 自身の操作に割り当てられている打鍵**に限ってこの形を解釈します。
割り当てを変えれば解釈する対象も一緒に変わるので、キーを付け替えたときだけ効かない、という
ことは起きません。

その代わり、**ttyskk が解釈するキーに子アプリが割り当てている操作は使えなくなります**。
Claude Code で改行を入れたいときは `Shift+Enter` か `\` + `Enter` を使ってください。また、
このプロトコルの下では `ascii_keys` による ASCII 復帰は効きません (あれは子アプリが自分の
操作に使っているキーへの便乗で、形を変えると子アプリの操作まで変わってしまうためです)。

**割り当てから外したキーは、このプロトコルの下では ttyskk に届かなくなります。** 素の形に
戻す対象が割り当て一覧だからです。戻せなかったキーは割り当ての無いキーとして素通りするので、
`▽` の途中で押すとそこで見出し語が確定してしまいます。手前の一文字を消すキーを増やすときは
`backspace` に足してください (既定は `BS` と `C-h` の両方です)。

なお、消すものが無いときの `C-h` は押されたキーのまま子アプリへ渡します。`0x7f` に揃えたり
はしません —— `<C-h>` に別の働きを割り当てているアプリで、それが効かなくなるためです (nvim
の窓の移動がそうです)。`C-h` に一切触らせたくなければ `backspace = ["bs"]` と書きます。

### 貼り付け

端末は貼り付けた内容を `CSI 200~` と `CSI 201~` で挟んで送ります。**挟まれた中身は打鍵では
ないので、ローマ字変換にもモード切り替えにも回しません。** モードが何であっても、貼ったもの
は貼ったとおりに入ります。

変換の途中で貼った場合は、見出し語や候補を先に確定してから貼り付けを流します。辞書登録の
途中で貼った場合だけは、子アプリへ出さずに登録内容へ足します。

## 仕組み

ttyskk が画面に対して守っている決まりは四つです。

- **画面の内容には触りません。** 書くのは重ね描きとカーソルの見た目だけで、画面の格子の中身
  は一切書き換えません。`TTYSKK_NO_CURSOR` を設定すると本当に 1 バイトも書かなくなり、素の
  実行とバイト単位で一致します
- **常設の行を作りません。** 最下行にモード表示を置かないので、子アプリの画面配置を乱しません
- **変換の途中の文字は重ね描きです。** 子アプリには送らないため、変換を取り消しても向こうには
  何も残りません
- **カーソル位置が分からないうちは描きません。** 原点がずれた状態で描くと、無関係なセルを
  潰したうえにカーソルまで誤った場所へ動いてしまいます。壊すくらいなら描きません

不具合を追うときは `TTYSKK_DEBUG` にファイルの場所を渡すと、画面の控えのカーソル位置・子
アプリの出力・打鍵ごとの重ね描きを書き出します。

変換エンジン (`src/lib.rs`) と、端末に載せる部分 (`src/main.rs`) に分かれています。エンジン
は画面まわりを一切持たないので、別の入力メソッドにも載せられます (実際に fcitx5 の addon が
これを使っています)。

```toml
[dependencies]
ttyskk = { version = "0.3", default-features = false }
```

内訳と、エンジンを直接使うときの呼び方は [`docs/design.md`](docs/design.md) にあります。
なぜこの作りにしたかの記録は [`NOTES.md`](NOTES.md) です。

## 入れないもの

理由を添えて、追わないと決めたものです。

- **候補一覧の縦並び** —— ddskk の既定はエコーエリアへの横並びで、CorvusSKK も縦は設定項目
  です。縦なのは skkeleton だけで、それは Vim の一覧に乗せているためです。行内の横並びと、
  カーソルの下に一行で浮かせる形 (`float`) で足ります
- **数値変換の `#4` (数値再変換)** —— `SKK-JISYO.L` にあるのは 1 件だけで、
  `SKK-JISYO.noregist` (登録すべきでない項目の一覧) には 9 件あり、いずれも「再帰数値変換の
  意味がない?」と注記されています。標準辞書の側が使わないよう促している指定です
- **skkserver** —— 辞書ファイルを分け合えば足ります
- **SandS (空白を Shift として使う打ち方)** —— 端末では**キーを離した通知が届きません**。
  kitty 鍵盤プロトコルなら取れますが、空白は文字を生むキーなので
  `report all keys as escape codes` が必要で、有効にすると**すべての打鍵がエスケープ列に
  なり、文字が送られてこなくなります**。ttyskk が鍵盤プロトコルの翻訳器になってしまいます。
  さらに SKK では**空白が既に変換キー**で、単打の意味が状態によって変わります。入れるなら
  入力の最下層 (xremap など) が向いています
- **確定した文字列の再変換** —— 子アプリの持ち物になった文字には触れません。直したい語は
  確定する前に (`▽` の中で) 直してください

`▽` の外では、矢印キーは見出し語を確定してから子アプリへ渡します。SKK は語ごとにその場で
確定させるので、文節をまたぐカーソル移動は要らないためです。

## English

`ttyskk` is an SKK Japanese input method that lives entirely inside your terminal.

It wraps a child process in a pseudo-terminal, intercepts the keys you type, and passes
only *confirmed* text to the child. Text that is still being converted is painted onto
the terminal as an overlay, so it never enters the child application's screen at all.

Because the input method sits at the terminal-application layer, keys always flow in the
order "multiplexer → ttyskk → child". This structurally removes the key contention you get
when a desktop-level input method and your terminal multiplexer both want `Ctrl+Z`.

The same conversion engine also runs as an fcitx5 input method, sharing one dictionary and
one set of learned words with the terminal side.

```sh
cargo install ttyskk
sudo apt install skkdic     # or: pacman -S skk-jisyo
ttyskk                      # wraps $SHELL
ttyskk -- claude            # wraps a specific command
```

Press `Ctrl+J` to switch to kana input, type a word starting with a capital letter to begin
conversion, and press `space` to convert.

The rest of the documentation is in Japanese, as its readers are.
