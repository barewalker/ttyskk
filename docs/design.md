# 設計

README の「仕組み」で触れた決まりの詳細と、部品の分かれ方です。なぜこの作りにしたかという
記録は [`NOTES.md`](../NOTES.md) にあります。

## 画面に対して守っていること

- **画面の内容には触りません。** 書くのは重ね描きとカーソルの見た目だけで、画面の格子の中身
  は一切書き換えません。ASCII モードで書くのはカーソルの形と色 (モードの合図) だけなので、
  `less` のような全画面のアプリの表示も乱れません。`TTYSKK_NO_CURSOR` を設定すると本当に
  1 バイトも書かなくなり、素の実行とバイト単位で一致します (起動時のカーソル位置の問い合わせ
  だけは残りますが、画面には現れません)
- **常設の行を作りません。** 最下行にモード表示を置かないので、端末のスクロール領域に触れず、
  子アプリの画面配置を乱しません
- **変換の途中の文字は重ね描きです。** 子アプリには送らないので、変換を取り消しても向こうには
  何も残りません
- **カーソル位置が分からないうちは描きません。** 重ね描きの基準を得るため、子アプリを起こす
  前に `CSI 6n` を送ります (このときは子アプリがまだ何も出力していないので、応答が混ざりま
  せん)。以降は子アプリの出力を横から読んで画面の控え (`src/screen.rs`) を保ちます。
  **原点がずれた状態で描くと、消去が無関係のセルを空白で潰し、物理カーソルまで誤った場所へ
  動くのでシェルの出力がそこへ落ちます** —— 打った文字が消えたように見えます。壊すくらいなら
  描きません。尋ね直すのは画面サイズの変更後 (折り返しが組み直されて絶対位置が変わります) と、
  かなモードへ入った瞬間 (重ね描きを始める直前で、子アプリが静かなことがほとんどです) です。
  応答を待つのは 1.5 秒で、mosh のような遅い経路でも取りこぼさないようにしています。子アプリ
  が描き直し始めたあとに届いた応答は、古いものとして捨てます
- **エスケープ列の途中には割り込みません。** 子アプリの出力が読み取りの境界で切れている間は
  重ね描きを控えます (`src/input.rs` の `SeqTracker`)
- **書き戻したらカーソルを戻します。** 重ね描きの消去は控えの内容を書き直すので、カーソルと
  表示属性が動きます。子アプリは自分が居た場所に書くつもりなので、子アプリの出力を流す前に
  必ず戻します。戻さないと子アプリの文字が一つずれた場所に落ちます

不具合を追うときは `TTYSKK_DEBUG` にファイルの場所を渡すと、控えのカーソル位置・子アプリの
出力・打鍵ごとの重ね描きを書き出します。指定しなければ何も書きません。

## 部品

変換エンジン (`src/lib.rs`) と、端末に載せる部分 (`src/main.rs`) に分かれています。エンジン
は画面まわりを一切持たないので、別の入力メソッドにも載せられます。

| ファイル | 役割 | |
|---|---|---|
| `src/skk.rs` | SKK の状態機械 | エンジン |
| `src/romaji.rs` | ローマ字からかなへの変換表 | エンジン |
| `src/dict.rs` | 辞書の読み込み・引き当て・学習 | エンジン |
| `src/config.rs` | 設定ファイルの読み込みと見張り | エンジン |
| `src/context.rs` | 画面の文脈による候補の並べ替え | エンジン |
| `src/num.rs` | 数値変換 (`#` の抜き出しと戻し) | エンジン |
| `src/main.rs` | 擬似端末と入出力の仲介 | 端末 |
| `src/screen.rs` | 画面の控え (文字と表示属性の格子) | 端末 |
| `src/render.rs` | 重ね描きと、控えからの書き戻し | 端末 |
| `src/input.rs` | 入力バイト列のキーへの切り出し | 端末 |

GUI の入力メソッドは、この上にもう二層を重ねた形です。

| 場所 | 役割 |
|---|---|
| `capi/` | C ABI の層 (cbindgen がヘッダを作ります) |
| `fcitx5/` | fcitx5 の addon (C++) |

作りは [`fcitx5-addon.md`](fcitx5-addon.md) にまとめてあります。

## エンジンだけを使う

端末側の依存 (擬似端末・端末制御) を落とせます。

```toml
[dependencies]
ttyskk = { version = "0.3", default-features = false }
```

キーを一つずつ `Skk::handle` に渡し、返ってきた `Response` を出力に回します。入力中の表示は
`Skk::preedit`、候補の一覧は `Skk::candidates` で、いずれも組み上げる前の形で取れます。

`Response` は**確定した文字列と、解釈しなかったキーを分けて**返します。

```rust
pub struct Response {
    pub commit: String,             // 確定した文字列
    pub passthrough: Option<Key>,   // 解釈しなかったキー
    pub mode_changed: bool,
}
```

この二つは同時に起きます —— `▽` の途中で矢印を押すと、見出し語を確定したうえで矢印を渡し
ます。端末ではどちらも子プロセスの標準入力という同じ出口へ流すので `Response::to_child()` で
一本のバイト列に組めますが、GUI の入力メソッドでは前者が「文字列の確定」、後者が「このキーは
使わなかった」というまったく別の知らせになります。分けてあるのはこのためです。
