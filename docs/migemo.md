# migemo — ローマ字から日本語を探す正規表現を作る

`ttyskk migemo kaigi` が `(?:kaigi|かいぎ|カイギ|会議|回議|懐疑|…)` を吐くようにする。
実装はまだ無い。ここは着手前の見取り図。

この文書だけで着手できるように書いてある。呼び出す側 (Neovim) の事情も含む。

## なぜ作るか

いま同じことを **kensaku.vim** がやっている。これが Deno に依存している。

```
kensaku.vim → denops.vim → Deno (/usr/sbin/deno, 113 MB, dpkg 管理外の手置き)
```

加えて kensaku は初回起動時に **辞書を GitHub から取ってくる**。
`migemo-compact-dict` (2.1 MB) が `~/.cache/kensaku.vim/` に落ちている。
つまり Deno という常駐処理系と、ネットワーク越しの辞書取得の二つが外部依存になっている。

skkeleton を消し、ddc も消した結果、**Deno はいま kensaku のためだけに存在している**。
一方 ttyskk は入力メソッドとして既に入っていて既に動いている。ここに移せば依存が一つ減る。

### 誰が使っているか

| 使う側 | 何に使うか |
|---|---|
| fzfkasten.nvim | 5 つのピッカーの `<alt-/>` (ノート検索・リンク挿入・内容検索・タスク・タスク一覧) |
| kensaku-search.vim | `/` 検索でローマ字を打つ (コマンドラインの `<CR>` を乗っ取っている) |

**この二つが移行先になる。** fzfkasten 側の差し替えは別セッションでやるので、
ここでは触らない (「やらないこと」を見よ)。

## migemo とは何か

**ローマ字→かな変換ではない。** `kaigi` から作る正規表現は `かいぎ` `カイギ` に加えて
**漢字 (`会議` `回議` `懐疑` …)** にも当たる。漢字に当てるには「読み → 見出し語」の
辞書引きが要る。

migemo の辞書はもともと SKK-JISYO から生成されたものなので、**ttyskk が持っている
辞書と同じ素性**である。

## 出来上がりの姿

```
ttyskk migemo [--flavour vim|rg] [--limit N] <query>
```

- 標準出力に正規表現を一行。末尾の改行はあってよい。
- 終了状態 0 = 正規表現を作れた。
- 終了状態 非0 = 作れなかった (辞書が無い、引数が無い等)。理由は標準エラーへ。
- `--flavour` 既定は `rg`。
- `--limit` は候補数の上限 (後述。既定は実測して決める)。

**空の入力に空を返してはいけない。** 呼び出し側は「空文字 = 失敗」として扱い、
いま掛かっている絞り込みを維持する。これは kensaku が denops 起動待ちのあいだ
`''` を返す仕様に合わせたもので、そのまま踏襲してよい。引数無しは終了状態 非0 とする。

### なぜ常駐させないか

`<alt-/>` は打鍵ごとではなく、利用者が絞り込みを確定した時に一度だけ走る。
プロセス起動一回分は許容範囲にある。**まず (a) 単発起動で作って測る。**

懸念は毎回の辞書読み込み。`~/.skk/` は 21 MB ある。ここが支配的だと分かった場合、
対処は常駐化ではなく **索引の事前生成** にする (`ttyskk migemo --build-index` のような形
で読みだけを取り出した小さな索引を作り、以後はそれを読む)。常駐は denops と同じ構造に
戻ることになるので、最後の手段。

## 出力の形

kensaku の実測出力を `tests/kensaku-reference.json` に置いた。2026-07-29 に
`kensaku#query()` を直接呼んで取ったもの。要点を抜くと次のとおり。

```
kaigi     → (?:kaigi|かいぎ|カイギ|会議|回議|怪魚|懐疑|改行|海[技魚]|解義|詼謔|諧謔|
             買(?:玉|い玉)|開業|ｋａｉｇｉ|ｶｲｷﾞ)
gijiroku  → (?:gijiroku|ぎじろく|ギジロク|議事録|ｇｉｊｉｒｏｋｕ|ｷﾞｼﾞﾛｸ)
2026      → (?:2026|２０２６)
ltu       → (?:[っッｯ]|ltu|ｌｔｕ)
```

読み取れる規則:

1. **並びは** 入力そのもの → ひらがな → カタカナ → 漢字候補 → 全角英数 → 半角カナ。
   順序に意味は無いが、揃えておくと差分を読むのが楽。
2. **共通接頭辞をまとめている。** `海技` と `海魚` は `海[技魚]`、`買玉` と `買い玉` は
   `買(?:玉|い玉)`。jsmigemo の TernaryRegexGenerator による木構造の圧縮。
3. **一文字の候補は文字クラスに集める。** `ltu` の `[っッｯ]`、`todo` の
   `[停屆届椴止滞滯畄留軣轟閼]`。
4. **空白は語の区切り。** `kaigi roku` → `(?:…)(?:…)` と連結される。
5. **大文字はそのまま。** `Kaigi` → `Kaigi|かいぎ|…|Ｋａｉｇｉ|ｶｲｷﾞ`。
   ローマ字の字面と全角化は大小を保ち、かなは保たない。
6. **半端なローマ字も扱う。** `kaig` → `かい[がぎぐげごっ]` に展開し、その読みで始まる
   見出し語を引く。`ttyskk` → `っtysっ` のように、かなにならない部分は字面で残る。

### 文字列一致は求めない

kensaku の辞書は `migemo-compact-dict` (2.1 MB の整形済み)、ttyskk の辞書は
`~/.skk/` の SKK-JISYO 一式 (21 MB)。**候補の集合は必ず違う。**
`tests/kensaku-reference.json` は「形の見本」と「当たるべきものの目安」であって、
期待値ではない。受け入れ条件は後述の差分試験で測る。

## 正規表現の方言

**二つ要る。** 片方だけ作ると、ripgrep を使う内容検索だけが静かに何も見つけなくなる。
これは fzfkasten で実際に起きた不具合 (`427e245`) で、`\%(` `\|` を rg に渡していた。
**引数として最初から設計に入れること。** 後から足す形にしない。

| | `vim` | `rg` |
|---|---|---|
| prefix | `\m` | (無し) |
| or | `\|` | `\|` |
| startGroup | `\%(` | `(?:` |
| endGroup | `\)` | `)` |
| startClass | `[` | `[` |
| endClass | `]` | `]` |
| newline | (空) | (空) |
| escape | `\.[]*~^$` | `\.[]{}()*+-?^$\|` |

(kensaku の `g:kensaku#rxop#vim` と `g:kensaku#rxop#javascript` の実物。
`autoload/kensaku/rxop.vim` にある。)

`vim` 方言は先頭に `\m` を付ける。`escape` は **その方言で特別な意味を持つ文字の集合**
で、候補の文字列中にこれらが現れたら `\` を前置する。辞書には `＋` `（` `／` のような
記号を含む見出し語があるので、ここを省くと壊れた正規表現が出る。

## ttyskk 側で使える部品

**発明が要る部分は無い。** 既にある公開 API の組み立てで作れる。

| 要るもの | 現物 |
|---|---|
| ローマ字 → かな | `romaji::Romaji::feed` (AZIK 対応、未確定綴りは `pending()`) |
| かな → カタカナ | `romaji::to_katakana` |
| かな → 半角カナ | `romaji::to_hankaku_katakana` |
| 英数 → 全角 | `romaji::to_zenkaku` |
| **読みの前方一致** | `dict::Dict::complete(prefix, limit)` |
| 読み → 見出し語 | `dict::Dict::lookup(key)` |

`Dict::complete` が決め手。`system_prefix_range` が
`partition_point` による二分探索で、送り仮名あり見出し語 (`is_okuri_ari`) も除いてある。
migemo が必要とする操作そのもの。

```rust
fn system_prefix_range(&self, prefix: &str) -> &[String] {
    let lo = v.partition_point(|k| k.as_str() < prefix);
    let hi = v.partition_point(|k| k.as_str() < prefix || k.starts_with(prefix));
```

置き場所は `src/migemo.rs` を新設し、`lib.rs` に `pub mod migemo;` を足す形が素直。
サブコマンドは `main.rs` の `std::env::args()` を回している箇所 (681 行目あたり、
`-h` `--version` `--import` などを見ているところ) に足す。

**擬似端末を要求しないこと。** `ttyskk` 本体は tty が要るが、`migemo` は
パイプの先から呼ばれる。引数を見た時点で分岐し、端末まわりの初期化に入らないようにする。

## 手順

1. `src/migemo.rs` に `Rxop` (方言の表) と `build(query, rxop, limit) -> String` を置く。
2. ローマ字を語に分け、語ごとに かな・カタカナ・半角カナ・全角英数 を作る。
3. 各語の読みで `Dict::complete` と `Dict::lookup` を引き、見出し語を集める。
4. 集めた候補を木に入れ、共通接頭辞をまとめて正規表現にする。
   **最初は平坦な連結でよい** — ただし 5. の長さを必ず測ること。
5. **長さの上限を決める。** kensaku の `a` は 1483 文字、`n` は 1035 文字だった。
   SKK-JISYO は migemo-compact-dict より大きいので、平坦に並べると跳ね上がる。
   ripgrep には `--regex-size-limit` があり、Vim の正規表現にも実務上の限界がある。
   `--limit` の既定値は**実測して決める**。一文字の入力を必ず測ること。
6. サブコマンドを `main.rs` に足す。
7. 試験を書く (次節)。

## 受け入れ条件

### 1. 差分試験 — 文字列ではなく「当たるか」で測る

`tests/kensaku-reference.json` の各入力について、**ttyskk が作った正規表現が
kensaku の候補に当たるか**を見る。当たるべき文字列の一覧は同ファイルの kensaku 出力から
取り出せる (`|` で割って群を外す)。

- **通すべき**: `kaigi` の正規表現が `会議` `かいぎ` `カイギ` `kaigi` `ｶｲｷﾞ` に当たる。
- **落としてよい**: `詼謔` のような、辞書の違いで出ない候補。ただし**何が落ちたかは
  出力すること**。黙って減ると、後から「絞り込めているつもりで漏れている」形の
  不具合になる。

### 2. 実データでの回帰

`~/zettelkasten/` が実際の使い道。ここを対象に、いくつかの入力で
「kensaku で当たる行」と「ttyskk で当たる行」を突き合わせる。**行数の差ではなく
差分そのもの**を見る。

### 3. 二つの方言が両方とも動く

`--flavour vim` の出力を `vim.fn.match()` に、`--flavour rg` の出力を実際の
`rg` に食わせて、同じ文字列に当たることを確かめる。**片方だけ試して通したことにしない。**

### 4. 速さ

`<alt-/>` を押してから一覧が入れ替わるまでが体感の対象。目安として
**warm な状態で 100 ms 以内**。超えるなら索引の事前生成へ。
`hyperfine` などで測り、辞書読み込みと正規表現組み立ての内訳を出すこと。

## やらないこと

- **fzfkasten.nvim を触らない。** 呼び出し側は別セッションでやる。あちらの
  `lua/fzfkasten/kensaku.lua` は既に独立した変換層になっていて (`available` /
  `regex` / `rg_regex` / `matches` / `prompt` / `header_hint`、試験 32 件)、
  差し替え可能なバックエンドに一般化する。この文書の担当は `ttyskk migemo` まで。
- **kensaku.vim を消さない。** 差分試験の相手として要る。移行が済むまで残す。
- **fcitx5 / capi を触らない。** 単発起動で足りるかを先に測る。FFI はその後の話。

## 落とし穴

- **半角カナの濁点は二文字。** `ぎ` → `ｷﾞ`。一文字対応の表を作ると壊れる。
- **`ん` の扱い。** `shinnyuu` は `しんゆう` になる (`nn` → `ん`)。`Romaji::feed` が
  既に面倒を見ているので、自前で書き直さないこと。
- **`escape` を方言ごとに変える。** 上の表のとおり、集合が違う。`-` は rg 方言では
  逃がすが vim 方言では逃がさない。
- **入力が一文字のとき。** 候補が数千件になる。ここで上限が効くかを最初に確かめる。
- **`~/.skk/` が無い環境。** 終了状態 非0 と、何が足りないかを標準エラーへ。
  呼び出し側はこれを「kensaku が使えない」と同じ扱いにして、`<alt-/>` を隠す。

## 実測 (実装後に追記)

この見取り図に沿って `src/migemo.rs` に実装した。**実測して決める**としてあった箇所の答え。

### 長さの上限 — `--limit` の既定は 1000

上限を 100 から 2000 まで動かしても**所要時間は変わらなかった** (辞書を読む分が支配的)。
変わるのは出来上がりの長さだけなので、上限は長さのためだけに置く。

| `--limit` | `a` | `n` |
|---|---|---|
| 100 | 279 B | 363 B |
| 200 | 560 B | 615 B |
| 1000 | 1253 B | 1127 B |
| 2000 | 1795 B | 1568 B |

一字候補が文字クラスにまとまるので、案じたほどは伸びない。1000 は kensaku の同じ入力
(`a` = 1483 文字) と釣り合う長さで、ripgrep の `--regex-size-limit` にも Vim にも余裕がある。

### 速さ — 索引が要る

単発起動のまま測ると **220 ms**。目安の 100 ms を超えており、内訳は次のとおりだった。

| | |
|---|---|
| 共有辞書 (SKK-JISYO.L 4.5 MB) を読む | 212 ms |
| 正規表現の組み立てと起動 | 8 ms |

読み込みが支配的なので、見取り図のとおり**常駐ではなく索引の事前生成**へ回した
(`ttyskk migemo --build-index`)。読みと見出し語だけを UTF-8 の平らな表 (4.2 MB、
159,325 件) に落とし、二分探索で必要な範囲だけ拾う。

| | |
|---|---|
| 索引あり | **26 ms** (一字入力でも 32 ms) |
| 索引なし (辞書をそのまま読む) | 220 ms |

索引が無くても、元の辞書と合わなくなっても動く — 遅いだけで答えは変わらない。

### 差分試験 — kensaku の候補 1643 / 2574 件に当たる

`tests/migemo_reference.rs`。落ちた分の内訳は次のとおりで、**辞書とローマ字表の違いで説明が付く**。

- **英単語・学名** (`a` `n` `A` で計 900 件) … `ASCII` `NASA` `Celastraceae` など。
  migemo-compact-dict 固有で SKK-JISYO には無い。
- **送りあり見出し由来の単漢字** (`todo` の `停` `止` `滞` など) … ttyskk は送りありを索引から
  外している (読みが途中で切れていて前方一致に使えないため)。
- **`ltu`** … ttyskk の標準ローマ字では小書きは `x` 前置 (`xtu`)。`l` 前置は AZIK の綴り。
  `ttyskk migemo xtu` は `(?:[っッｯ]|xtu|ｘｔｕ)` を返す。
- **`ttyskk` の `っtysっ`** … 末尾の半端な綴りを展開する (`っtysっ[かきくけこっ]`) ので、
  展開前の形には当たらない。`kaig` を `かい` まで戻さないのと同じ扱い。打ちながら
  絞り込む道具なので、緩めるより絞る側に倒した。

### 実データでの回帰 — `~/zettelkasten` (270 ファイル)

kensaku の出力 (参照 JSON) と ttyskk の出力を、それぞれ `rg` に食わせて当たった行を突き合わせた。
**17 件中 13 件が完全に一致**。差が出たのは 4 件。

| 入力 | kensaku | ttyskk | ずれ |
|---|---|---|---|
| `tokyo` | 0 行 | 33 行 | ttyskk が `東京` を拾う (kensaku には無い) |
| `note` | 73 行 | 92 行 | ttyskk が `ノート` を拾う。逆に `ノーツ` `≠` が 2 行落ちる |
| `todo` | 216 行 | 90 行 | kensaku は `止` `留` 等の単漢字にも当たる |
| `ltu` | 2351 行 | 2 行 | kensaku は促音を含む全行に当たる |

`todo` と `ltu` の差は上記のとおり。どちらも kensaku 側が広く当たっているが、
`ltu` で 2351 行 (ほぼ全部) に当たるのは絞り込みとしては役に立たない。

### 二つの方言

`tests/migemo_reference.rs` の `both_flavours_hit_the_same_strings` で、rg 方言は regex crate
(ripgrep と同じもの)、vim 方言は `nvim --headless` の `match()` に実際に食わせている。
逃がす文字の集合が方言で分かれる `-` を必ず混ぜてある。
