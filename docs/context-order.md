# 画面の文脈で候補を選び分ける

同音異義語の順序を、いま見えている文章から決める仕組みです。README に概要があります。ここ
では重みの決め方と、効き方の測り方を説明します。

```toml
[behavior]
context_order = true          # 既定です
context_half_distance = 200   # 重みが半分になる距離 (文字数)
```

## 二つの手掛かり

どちらも**辞書に既にある情報**を使います。余分なファイルは持ちません。

1. **候補そのものが画面にあるか。** 文章は同じ語を繰り返します。「講演」の話をしている画面
   には、たいてい既に「講演」が出ています
2. **注釈の共起語が画面にあるか。** `SKK-JISYO.L` は `校正;proofread.「新聞の-」` のように
   用例と訳語を注釈に持っています。画面に `proofread` や「新聞」があれば校正が上がります。
   **英語も見ます**

注釈から取るのは**鉤括弧の中の漢字の連なり**と英単語です。括弧の外まで拾うと、`夛;「多」の
異体字` の「異体字」のような**語の説明**まで共起語になってしまうためです。`and` や `the` の
ような機能語は手掛かりにしません (英文がある画面ならどこでも当たってしまい、無関係な候補が
上がるためです)。

## 距離の重み

カーソルから遠いほど軽く見ます。**冪関数を使います** —— 指数関数は遠くを消しすぎるためです。
文書の冒頭に一度だけ書かれた語が手掛かりになることは多く、指数だとその手掛かりが残りません。

```
w(d) = 1 / (1 + d/λ)      λ = context_half_distance (既定 200)
```

**距離は文字数**で数えます。行数ではありません —— 一行の文字数はフォントの大きさや多重化器
の分割で変わるので、行を単位にすると環境ごとに効き方がぶれるためです。

| カーソルからの距離 | λ=100 | **λ=200** | λ=400 |
|---|---|---|---|
| 40 文字 | 0.71 | **0.83** | 0.91 |
| 200 文字 | 0.33 | **0.50** | 0.67 |
| 800 文字 | 0.11 | **0.20** | 0.33 |
| 2600 文字 | 0.04 | **0.07** | 0.13 |

λ を小さくすると近くだけを見ます (話題が細かく切り替わる文書向きです)。大きくすると画面全体
を平らに見ます (一つの話題が続く長文向きです)。同じ語が何度も出てくれば足し合わせるので、
「近い」と「よく出る」の両方が効きます。

注釈から来た手掛かりは、候補そのものより弱く見ます (重み 0.5)。「画面にその語がある」は直接
の証拠ですが、「注釈に書かれた共起語がある」は間接で、辞書の書き手の主観も混ざるためです。

## 数えないもの

一文字の候補は、**同じ字種の連なりがちょうどその一文字**のときだけ数えます。「公」が「公園」
「公演」の中に当たっては信号になりません。

英語は語の境界で見て、`src/main.rs` や `--config-example` のような**識別子やパスの一部は
数えません** (人の文章ではないためです)。

**数字だけの候補も数えません。** 辞書には数字そのものが候補として入っています
(`いち /一/位置/市/壱/…/１/1/`)。端末の画面は数字で埋まっているので必ず当たってしまい、
「いち」と打つと位置より `1` が先に出ます。数字は話題を示さないので、手掛かりとして意味を
持ちません。

**数字に続く漢字一文字も数えません。** 「180 行」「41 件」「3 回」の助数詞です。漢字の
連なりとしてはちょうど一文字なので、上の規則だけでは通ってしまいます。編集器の状態表示や
試験の結果に必ず出る形で、実際に「あん」と打つと案より「行」(行脚) が先に出ました。桁を
揃える空白は読み飛ばして数字を探します。

**「第1案」「第2章」は数えます。** 数字の前に「第」があれば、数を数えているのではなく番号を
振った語なので、本物の手掛かりとして働きます。進め方を書いた画面に「第1案」が並んでいれば、
「あん」で案が上がります。

助数詞の一覧は持ちません (語の表を抱えることになるためです)。そのため「第」の付かない
`1案` `2章` のような書き方は手掛かりになりません。

## 辞書の並びを一気に飛ばさない

**ほとんど使わない読みは、画面に字があるだけでは先頭に来ません。**「あん」の「行」は
`SKK-JISYO.L` で 17 件中 16 番目にあり、注釈も `行脚` だけです。この読みはそこでしか使い
ません。それが「行」という語について書いている画面で 1 番目に来ると、案を押しのけてしまい
ます。

**上位 5 件まではこれまでどおり**で、6 番目以降に二つの手当てをします。

1. **一文字の候補は、それが画面にあることを数えません。** 画面に「行」とあることは
   **その字についての証拠で、読みについての証拠ではありません** — 画面の「行」はまず
   「ぎょう」「こう」「いく」です。上位の候補なら字の一致で足ります (ふつうに使う読みだから)
   が、下位ではその字が別の読みで使われていると見るのが自然です。**二文字以上の語は下位でも
   数えます** — 「鋼製」のように読みがほぼ一つに決まる語は、画面にあることがそのまま読みの
   証拠になります (辞書 11 番目・注釈なしでも、鋼製の話が続く画面では先頭に来ます)
2. **位置に応じて点数から引きます。** `0.3 × ln((1 + 位置) / 5)`

**注釈の用例語は下位でも信用します。** これが「行」と「較正」を分ける境目です。
「較正;calibrate.「計器の-」」の計器は読みと意味に結び付いているので、画面にそれがあれば
辞書 15 番目でも先頭に来てよいことになります (`tests/context-sample.md` の六がこれです)。

上位 5 件を外してあるのは、**ふつうの選び分けがそこで起きる**ためです。画面に「構成」と
「校正」が両方あってカーソルが校正寄り、という場面は距離の差が 0.03 しかなく、罰を掛けると
潰れます。

**押し下げには使いません。** 罰が勝つときは 0 で止まるので、手掛かりの弱い候補は元の位置に
留まるだけで、辞書順より下がることはありません。

係数は測って決めました。0.15・0.3・0.5 のいずれでも、問題集 40 件・既存の見張り 6 件・上の
僅差の場面がすべて同じ結果になります。効き方が鈍いところなので中間を採りました。

## 費用と、効かない場合

**手掛かりが無ければ並びを変えません。** 点数が全部 0 のときは触らないので、関わりの無い
画面で悪くなることはありません。費用は変換一回あたり 0.1〜0.2 ミリ秒で、打鍵のたびではなく
変換のたびにしか掛かりません。

引き換えに、**同じ読みが画面によって違う順で出る**ようになります。順序を指で覚えている方は
`context_order = false` にしてください。

## GUI (fcitx5) での違い

端末では子アプリの画面の控えを使えるので、**子アプリが書いた文字まで**手掛かりになります。
GUI で使えるのは fcitx5 の周辺テキスト、つまり**いま打ち込んでいる入力欄の中身**だけで、
画面に何が映っていても入力メソッドからは見えません。

- **効く場** …… 編集器・メールの本文・長い入力欄。書きかけの文章そのものが手掛かりになります
- **効かない場** …… 検索窓・一行のフォーム・アドレス欄。中身が数文字しかないので手掛かりが
  ありません。**画面に答えの語が見えていても関係ありません** (周辺テキストに入らないためです)
- **そもそも届かない場** …… 周辺テキストは子アプリが送ってくるもので、送らないアプリもあり
  ます (GTK/Qt の入力欄はおおむね送ります。端末エミュレータの中などは持ちません)

いずれも手掛かりが無ければ並びを変えないので、悪くなることはありません。

## 効き方を測る

効き方を測るための例文が `tests/context-sample.md` にあります。六つの節がそれぞれ違う話題を
持ち、**答えの漢字は文書のどこにも書いていない**ので、当たれば注釈の共起語が効いたことに
なります。

```sh
ttyskk -- nvim tests/context-sample.md
```

設定を変えて比べるときの基準として使えるよう、節の並び・読み・期待する候補は
`tests/context_sample.rs` で固定してあります。**この文書が変わると同じ基準で比べられなく
なります**のでご注意ください。

### 数で比べる

当たり外れではなく**正解が何番目に出るか**を数える台が別にあります。問題は
`tests/data/context-eval.toml`、走らせるのは次のとおりです。

```sh
cargo test --test context_eval -- --nocapture
```

順位から 1 を引いた数が、**空白を余計に押す回数**です。点数の付け方を変えたときに、
これが減ったか増えたかで判断します。問題は一件ずつ切り離してあり (上の例文は六件が一枚に
同居しています)、同じ読みを**正解が入れ替わる二つの文脈**で持ちます。後者がないと、順序を
決め打ちした実装でも満点が出てしまいます。

対照の問題 (手掛かりの無い画面) で並びが変わった場合と、偽の手掛かりで順位が上がった場合は
**試験として落ちます**。正解率は辞書の版で上下するので、数字の報告に留めています。
