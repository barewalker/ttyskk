# 画面の文脈で候補を選び分ける

同音異義語の順序を、いま見えている文章から決める仕組みです。README に概要があります。ここ
では重みの決め方と、効き方の測り方を説明します。

```toml
[behavior]
context_order = true          # 既定です
context_half_distance = 200   # 重みが半分になる距離 (文字数)
```

## 二つの手掛かり

どちらも**辞書に既にある情報**を使います。余分なファイルは持ちません。

1. **候補そのものが画面にあるか。** 文章は同じ語を繰り返します。「講演」の話をしている画面
   には、たいてい既に「講演」が出ています
2. **注釈の共起語が画面にあるか。** `SKK-JISYO.L` は `校正;proofread.「新聞の-」` のように
   用例と訳語を注釈に持っています。画面に `proofread` や「新聞」があれば校正が上がります。
   **英語も見ます**

注釈から取るのは**鉤括弧の中の漢字の連なり**と英単語です。括弧の外まで拾うと、`夛;「多」の
異体字` の「異体字」のような**語の説明**まで共起語になってしまうためです。`and` や `the` の
ような機能語は手掛かりにしません (英文がある画面ならどこでも当たってしまい、無関係な候補が
上がるためです)。

## 距離の重み

カーソルから遠いほど軽く見ます。**冪関数を使います** —— 指数関数は遠くを消しすぎるためです。
文書の冒頭に一度だけ書かれた語が手掛かりになることは多く、指数だとその手掛かりが残りません。

```
w(d) = 1 / (1 + d/λ)      λ = context_half_distance (既定 200)
```

**距離は文字数**で数えます。行数ではありません —— 一行の文字数はフォントの大きさや多重化器
の分割で変わるので、行を単位にすると環境ごとに効き方がぶれるためです。

| カーソルからの距離 | λ=100 | **λ=200** | λ=400 |
|---|---|---|---|
| 40 文字 | 0.71 | **0.83** | 0.91 |
| 200 文字 | 0.33 | **0.50** | 0.67 |
| 800 文字 | 0.11 | **0.20** | 0.33 |
| 2600 文字 | 0.04 | **0.07** | 0.13 |

λ を小さくすると近くだけを見ます (話題が細かく切り替わる文書向きです)。大きくすると画面全体
を平らに見ます (一つの話題が続く長文向きです)。同じ語が何度も出てくれば足し合わせるので、
「近い」と「よく出る」の両方が効きます。

注釈から来た手掛かりは、候補そのものより弱く見ます (重み 0.5)。「画面にその語がある」は直接
の証拠ですが、「注釈に書かれた共起語がある」は間接で、辞書の書き手の主観も混ざるためです。

## 数えないもの

一文字の候補は、**同じ字種の連なりがちょうどその一文字**のときだけ数えます。「公」が「公園」
「公演」の中に当たっては信号になりません。

英語は語の境界で見て、`src/main.rs` や `--config-example` のような**識別子やパスの一部は
数えません** (人の文章ではないためです)。

## 費用と、効かない場合

**手掛かりが無ければ並びを変えません。** 点数が全部 0 のときは触らないので、関わりの無い
画面で悪くなることはありません。費用は変換一回あたり 0.1〜0.2 ミリ秒で、打鍵のたびではなく
変換のたびにしか掛かりません。

引き換えに、**同じ読みが画面によって違う順で出る**ようになります。順序を指で覚えている方は
`context_order = false` にしてください。

## GUI (fcitx5) での違い

端末では子アプリの画面の控えを使えるので、**子アプリが書いた文字まで**手掛かりになります。
GUI で使えるのは fcitx5 の周辺テキスト、つまり**いま打ち込んでいる入力欄の中身**だけで、
画面に何が映っていても入力メソッドからは見えません。

- **効く場** …… 編集器・メールの本文・長い入力欄。書きかけの文章そのものが手掛かりになります
- **効かない場** …… 検索窓・一行のフォーム・アドレス欄。中身が数文字しかないので手掛かりが
  ありません。**画面に答えの語が見えていても関係ありません** (周辺テキストに入らないためです)
- **そもそも届かない場** …… 周辺テキストは子アプリが送ってくるもので、送らないアプリもあり
  ます (GTK/Qt の入力欄はおおむね送ります。端末エミュレータの中などは持ちません)

いずれも手掛かりが無ければ並びを変えないので、悪くなることはありません。

## 効き方を測る

効き方を測るための例文が `tests/context-sample.md` にあります。六つの節がそれぞれ違う話題を
持ち、**答えの漢字は文書のどこにも書いていない**ので、当たれば注釈の共起語が効いたことに
なります。

```sh
ttyskk -- nvim tests/context-sample.md
```

設定を変えて比べるときの基準として使えるよう、節の並び・読み・期待する候補は
`tests/context_sample.rs` で固定してあります。**この文書が変わると同じ基準で比べられなく
なります**のでご注意ください。
